# Етап 8: прийняті рішення

Завдання етапу: оцінити, чим можна пожертвувати за теоремою CAP (цілісністю, доступністю чи розподіленістю), що отримуємо натомість і як забезпечуємо надійність БД. Результат оформлено в розділі 9 звіту.

## Зміст аналізу

1. **Жертва для кожного сховища своя, а не одна на всю систему:**

   | Частина | Чим жертвуємо | Що отримуємо |
   | --- | --- | --- |
   | PostgreSQL | Розподіленістю (один вузол на сервіс) | Узгодженість, ACID |
   | MongoDB | Доступністю запису під час обрання нового primary | Підтверджений запис (`writeConcern: majority`) не губиться |
   | Elasticsearch, Neo4j, аналітика | Узгодженістю (асинхронне оновлення) | Доступність і швидкість читання |
   | Redis | Узгодженістю в межах TTL | Мінімальна затримка, без кешу система теж працює |

2. **Компенсація «в іншому місці»:**
   - поки MongoDB недоступна для запису, RabbitMQ накопичує пакети в черзі, тож приймання даних не зупиняється;
   - відставання пошуку й аналітики компенсується відображенням часу оновлення в UI.
3. **Лічильники на дашборді читаються з primary MongoDB.** Для демонстрації швидкості запису точність важливіша за доступність.
4. **PACELC згадано одним реченням.** Навіть без розділення мережі кеш і асинхронні проєкції дають швидкість ціною відставання даних.
5. **Надійність забезпечують:**
   - transactional outbox;
   - at-least-once доставка + ідемпотентна обробка;
   - версії сутностей;
   - черга для повідомлень, що постійно падають;
   - контрольні точки імпорту;
   - бекапи лише PostgreSQL і MongoDB, решта сховищ перебудовується з них.
6. **Репліки MongoDB.**
   - Базовий профіль: один вузол на шард. Дані розподілено, але failover немає.
   - Профіль із трьома вузлами на шард: є автоматичний failover. Подано як **додаткову мету** з посиланням на бонус до 10 балів за реплікацію.
7. **Застереження.** Аналіз описує цільову архітектуру. Поточний стенд працює на одній машині, де розділення мережі практично не виникає.
8. **Формат.** Розділ короткий: вступ із посиланням на розділ 8 (щоб не повторювати розподіл даних), таблиця 9.1, кілька абзаців.
