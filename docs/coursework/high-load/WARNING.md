# Увага перед оновленням на `main` після PR #1

Стан на 25.11.2026, `b6cec10`.

## 1. На Docker це ще не запускали

Код перевірено тестами та на тимчасових PostgreSQL і шардованому MongoDB 8.3 (без Docker). Справжній RabbitMQ, Compose-стенд і MongoDB 7.0 з цим кодом **не запускались**. Перш ніж будувати щось зверху, підніміть стенд і зробіть короткий запис:

```sh
python3 tools/ops/cs_ops.py up
python3 tools/ops/cs_ops.py start --rate 500       # друкує ID job
python3 tools/ops/cs_ops.py cancel --job ID        # за хвилину
python3 tools/ops/cs_ops.py verify --job ID        # має бути "ok": true
```

## 2. Дочекайтеся завершення імпортів до оновлення

Незавершені job мають продовжитись, але на справжньому стенді це не перевіряли. У старій версії скасування немає, лише пауза. `cs_ops.py cancel` працює тільки після оновлення.

## 3. `reset` стирає весь корпус стенду

`cs_ops.py reset --yes` очищає MongoDB, історію імпортів, черги та пошуковий індекс, **зокрема реальний корпус**. Потім `kaggle-cs` і `synthetic-cs` треба імпортувати знову. `purge` чіпає лише згенеровані `load-cs`.

## 4. Не відкочуйтесь на стару версію посеред імпорту

Outbox PostgreSQL тепер зберігає посилання, а не тексти. Старий код надішле такий рядок без документів, і job стане `failed`. Перед відкатом дочекайтеся завершення або скасуйте job.
