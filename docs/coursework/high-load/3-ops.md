# Коміт 3: `ops and load tools`

Файли: `deploy/`, `tools/ops/`, `tools/load/`, `requirements-load.txt`, `.env.example`, `tests/test_operations.py`, `tests/test_load_tools.py`, ця нотатка. Після коміту: 189 тестів проходять, 18 пропущено.

**З Docker це ще не запускалось**: на Mac його не було. Compose перевірено лише структурно, скрипт ініціалізації із заглушкою `mongosh`.

## Стенд (`deploy/`)

| Зміна | Навіщо |
|---|---|
| `--wiredTigerCacheSizeGB` (`WT_CACHE_GB`, 0,5) | без ліміту кожен mongod бере близько половини пам'яті VM |
| `--oplogSize` (`OPLOG_MB`, 2048) | інакше до 5 % вільного диска на ноду |
| `chunksize` 2 → 128 МБ | з 2 МБ балансувальник переносив би дані під час запису |
| Окремий `content_dispatcher` | worker можна масштабувати без дублів розсилки |
| Список шардів в env `SHARDS` | стенд на 1 або 3 шарди з того самого файлу |

## Консоль (`tools/ops/cs_ops.py`)

```sh
python3 tools/ops/cs_ops.py up                   # 3 шарди; --shards 1 up для одного
python3 tools/ops/cs_ops.py start --rate 0       # MAX, друкує ID job
python3 tools/ops/cs_ops.py status
python3 tools/ops/cs_ops.py shard kill 2         # потім shard start 2
python3 tools/ops/cs_ops.py verify --job ID
python3 tools/ops/cs_ops.py purge --percent 50 --yes
python3 tools/ops/cs_ops.py reset --yes          # стирає ВЕСЬ корпус стенду
```

Лише стандартна бібліотека, тому має працювати і на Windows. `reset` спершу зупиняє worker'и й чистить черги, інакше батчі з черги записалися б у порожню базу. Без `--yes` нічого не видаляється.

## Вимірювання (`tools/load/`)

- `run.py`: запускає сценарій і щосекунди пише швидкість, кеш, checkpoint, затримку запису та розміри по кожному шарду. Паралельно 10 читань за секунду.
- `scenarios/`: E1 (чи падає швидкість), E2 (пауза, рестарт, видалення), E3 (1 нода проти 3).
- `report.py`: таблиці та графіки. Для графіків потрібен `requirements-load.txt`.
- `host_probe.py`: нагрів Mac. Контейнери його не бачать, а перегрів виглядає як «база сповільнилась».

**Швидкість** береться з лічильників у Mongo, а не з черги. **Сповільнення**: медіана за 60 с нижча за 80 % медіани хвилин 2–5 протягом щонайменше 2 хв.

Пробний прогін ~2 хв (темп 5000, пауза, рестарт шардів, видалення половини) пройшов на справжніх API і кластері. Він знайшов дві помилки, обидві виправлено: конфлікт аргументів у раннері та темп 4500 замість 5000.

## Слабкі місця

- `restart_shards` розраховує, що Docker сам підніме контейнер (`restart: unless-stopped`).
- `pmset` на Apple Silicon не показує частоту, тому нагрів беремо з `notifyutil` (0 означає норму).
- Обидва стенди займають порт 8082, одночасно не піднімати.
